# Small reversible tasks

Use only when all apply: low consequence of error, reversible change, no mandatory control implicated, no new user research, no external write. Scope and product decisions remain the human's; a requested small fix does not authorize redesign or publication.

1. Load the full skill separately. Recover an existing task before creating anything. For a new eligible task, create the [five-line checkpoint](../assets/TASK-STATE-MINIMAL.md) at the normal task path before dependent reads; use `scripts/init_task_state.py --minimal` with the usual stdin request and refuse-overwrite behavior. Product-memory consultation still follows intake.
2. Keep the current checkpoint to request/affected users; decision to unlock; evidence actually consulted; next action/timebox; status. Unknowns remain unknown. Preserve any selected phase and the compact compass when known; do not impose a phase questionnaire or six rounds.
3. Do the smallest authorized useful action, inspect it and ask for any outstanding acceptance separately from a phase decision. Record actual sources, performer, confidence/limits and verification in the evidence line; keep user choices and pending acceptance in the decision/status lines.
4. Append dated five-line blocks with stable record IDs as material work changes; never overwrite the intake, failed/superseded work or earlier answers. Link an artifact instead of copying its contents. The five lines are a compact current view, not a cap on retained history.
5. Upgrade when any entry condition fails, a mandatory control appears or a second loop is needed. Preserve the complete old content at the same path, copy known facts into the full template and append the reason for upgrading; do not invent omitted phase work or restart intake. Without writes provide an explicitly unsaved checkpoint first.

Timebox expiry means review what is known and converge, narrow, loop or stop within the human's granted decision scope; it is not completion evidence. Never trade mandatory controls or honest status for speed.
Completing a method does not complete a phase or establish user acceptance.
Tool availability does not establish access or authority to act.
Proposed work remains separate from verified/observed results.

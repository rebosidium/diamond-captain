# Office tools for product and service design

Five additional categories, **ten optional candidates each**. Start with the team's existing workspace; this is a menu, not a ranking or installation checklist. Documents, meetings and spreadsheets are already covered in [categories 3, 4 and 24](tool-options.md#category-index). Read only the category needed for the next action.

Routes use the [main catalog legend and boundaries](tool-options.md#read-only-what-the-next-decision-needs): B = browser/app, F = compatible files, L = installed runtime, A? = inspect the current API. Discover actual connector/MCP operations first. A row is not proof of a connected account, MCP support for every operation, export compatibility or permission to write.

## Connector and MCP entry points

Read the [workspace connector routes and their limits](tools/office-connectors.md) when choosing a cloud workspace or API/MCP route. Keep actual capability, tenant access and concrete action authority separate.

## Source check and fallback

Provider references describe possible routes, not verified account access. Recheck current official documentation and inspect the exact live operation and scopes when needed; product availability and connector coverage can change.

If access is absent, use supplied EML/PDF/DOCX/PPTX/CSV/ICS or other compatible files, local drafts and a named owner for the blocked action. Check actual import/export compatibility; keep the original source and version. A drafted invitation, deck or approval request does not establish delivery, attendance or acceptance.

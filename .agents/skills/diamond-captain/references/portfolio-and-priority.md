# Choose among competing tasks

Open when several candidate problems compete for the same capacity, or the user asks what to do first. Skip this comparison for one already selected task. The human chooses priorities; prepare the comparison, one recommendation and its decisive uncertainty.

Method completion does not complete a phase or mean the user accepted the recommendation.
An available tool does not establish access or authority to change priorities, contact people or publish a plan.
Proposed effects and planned work are not verified evidence or observed outcomes.

## Compare only decision-relevant inputs

Reuse the relevant [product-memory](product-memory.md) index and cited evidence; preserve source dates and limits. Do not open unrelated task histories merely to fill the table. State the shared capacity, deadline and outcome being compared, or mark them unknown.

- Separate supplied facts, estimates and unknowns. Never invent reach, effect sizes, capacity or money to make candidates comparable. A consequential unknown can justify the smallest useful check first.
- State a mandatory constraint as a constraint, not a weighted preference; expected value does not override it. Escalate a conflict or missing necessary authority while continuing independent analysis.
- Do not present a composite score as objective. Explain which assumptions drive the recommendation and what evidence would change it.
- Distinguish choosing the next problem from selecting a solution inside it. Use [DS-12](methods/design-and-delivery.md#ds-12) for within-task option choice, [DS-13](methods/design-and-delivery.md#ds-13) for viability inputs and [QT-19](methods/quantitative.md#qt-19) for grounded cost-effectiveness inputs.

## Recommend a feasible sequence

Prefer a bounded first step that unlocks or invalidates other candidates, subject to mandatory constraints and a closing opportunity window. Name its information value, required inputs and dependency order; proposed capacity or ownership is not a commitment.

For each deferred candidate, record **not now + return trigger + owner**; use `unassigned` where necessary. Link the deferral result/decision record from a `paused` entry in the product-memory task index so its owner and trigger remain recoverable. For an unstarted candidate, label it `not started` and its state path `not created`; do not invent task history, an accepted assignment or a completed study. Keep another task's state untouched.

Present the recommendation and ask the consequential selection question unless the user already chose or specifically delegated it. Retain rejected/deferred candidates and reasons; update the comparison when its decisive evidence changes, not on every turn.

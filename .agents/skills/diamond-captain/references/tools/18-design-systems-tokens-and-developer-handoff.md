# 18. Design systems, tokens and developer handoff

Choose when the change must align design decisions, reusable components and implementation. Existing team components usually beat a new library.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Figma Dev Mode](https://www.figma.com/dev-mode/) | Inspect the team's existing design-to-code handoff | B |
| [Penpot](https://penpot.app/) | Shared components, tokens and design/engineering alignment | B / F |
| [Sketch](https://www.sketch.com/) | Existing Sketch libraries and developer specifications | B / F |
| [Storybook](https://storybook.js.org/) | Build and review implemented component states | L / F |
| [Chromatic](https://www.chromatic.com/) | Visual regression and shared component review | B |
| [zeroheight](https://zeroheight.com/) | Document and maintain a shared design system | B |
| [Supernova](https://www.supernova.io/) | Design-system knowledge and delivery workflows | B |
| [Tokens Studio](https://tokens.studio/) | Maintain and distribute design-token decisions | B / F |
| [Style Dictionary](https://styledictionary.com/) | Transform token files for multiple implementation platforms | L / F |
| [Docusaurus](https://docusaurus.io/) | Versioned, code-backed design-system documentation | L / F |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

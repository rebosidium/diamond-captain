# 1. Interface/flow design and prototypes

Choose when a concrete interaction or visual alternative needs to be explored. A clickable prototype is not a shipped implementation.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Figma](https://www.figma.com/) | Existing collaborative UI files and interactive flows | B / F |
| [Penpot](https://penpot.app/) | Open design workflow with web layout concepts | B / F |
| [Sketch](https://www.sketch.com/) | Mac-based design, libraries and existing Sketch files | B / F |
| [Axure RP](https://www.axure.com/) | Conditional, data-rich or form-heavy functional prototypes | B / F |
| [ProtoPie](https://www.protopie.io/) | Detailed motion, sensors and multi-device interactions | B / F |
| [UXPin](https://www.uxpin.com/) | Interactive prototypes with design/code component alignment | B |
| [Framer](https://www.framer.com/) | Responsive website prototypes approaching real content | B |
| [Webflow](https://webflow.com/) | Visually built responsive sites and CMS scenarios | B |
| [Balsamiq](https://balsamiq.com/) | Fast wireframes before investing in visual detail | B / F |
| [Marvel](https://marvelapp.com/) | Lightweight linked mockups and prototype feedback | B |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

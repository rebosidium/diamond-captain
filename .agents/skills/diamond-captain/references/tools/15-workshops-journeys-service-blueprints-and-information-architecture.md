# 15. Workshops, journeys, service blueprints and information architecture

Choose when people need to see causes, dependencies, navigation or front/backstage work together. A map is a hypothesis until grounded in evidence; these tools do not validate findability by themselves.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Miro](https://miro.com/) | Collaborative discovery, mapping and structured workshops | B |
| [FigJam](https://www.figma.com/figjam/) | Workshops alongside an existing Figma workflow | B |
| [Mural](https://www.mural.co/) | Facilitated collaborative workshops and synthesis boards | B |
| [Whimsical](https://whimsical.com/) | Lightweight flowcharts, navigation structures and wireframes | B |
| [Lucidchart](https://lucid.co/lucidchart) | Detailed process diagrams and dependency mapping | B |
| [draw.io](https://www.drawio.com/) | Portable flowcharts and service/process diagrams | B / F |
| [Excalidraw](https://excalidraw.com/) | Fast shared or local sketch-like diagrams | B / F |
| [Mermaid](https://mermaid.js.org/) | Versioned text-based flow, state or sequence diagrams | L / F |
| [Smaply](https://www.smaply.com/) | Journey management with linked service blueprints | B |
| [UXPressia](https://uxpressia.com/) | Journey maps, service blueprints and impact maps | B |

For navigation evidence, shortlist Lyssna, Useberry or Ballpark from category 6 and check the specific card-sort/tree/first-click operation before proposing it. Do not infer a capability from this cross-reference.

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

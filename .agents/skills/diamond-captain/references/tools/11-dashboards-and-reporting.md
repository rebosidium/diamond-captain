# 11. Dashboards and reporting

Choose when stakeholders need repeatable visibility or an inspectable outcome report. Reconcile metric definitions and access before sharing.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Looker](https://cloud.google.com/looker) | Governed business metrics with an existing semantic layer | B / A? |
| [Metabase](https://www.metabase.com/) | SQL or visual questions for team reporting | B / A? |
| [Power BI](https://www.microsoft.com/en-us/power-platform/products/power-bi) | Existing Microsoft data and reporting environment | B / F |
| [Tableau](https://www.tableau.com/) | Interactive exploration and established business reporting | B / F |
| [Apache Superset](https://superset.apache.org/) | Open-source SQL exploration and dashboards | B |
| [Redash](https://redash.io/) | Share existing SQL questions and dashboard results | B |
| [Grafana](https://grafana.com/) | Product/operations metrics alongside system health | B / A? |
| [Hex](https://hex.tech/) | Collaborative analytical work with app-like outputs | B |
| [Evidence](https://evidence.dev/) | Versioned analytical reporting from code and data | B / L / F |
| [Google Data Studio](https://datastudio.google.com/overview) | Shareable reports from existing supported data sources | B |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

# 17. Accessibility and inclusive experience checks

Choose when interaction, content or delivery needs accessibility verification. Automated findings cover only part of accessibility; combine relevant manual keyboard, assistive-technology and user checks. A passing scan is not a compliance certification.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [axe](https://www.deque.com/axe/) | Automated accessibility checks in browser or test workflows | B / L |
| [WAVE](https://wave.webaim.org/) | Inspect page accessibility issues in visual context | B / A? |
| [Accessibility Insights](https://accessibilityinsights.io/) | Guided automated and manual accessibility assessment | B / L |
| [Lighthouse](https://developer.chrome.com/docs/lighthouse/) | An initial automated web quality/accessibility signal | B / L |
| [NVDA](https://www.nvaccess.org/) | Manual Windows screen-reader interaction checks | L |
| [VoiceOver](https://www.apple.com/accessibility/features/?vision) | Manual Apple-platform screen-reader experience checks | L |
| [TalkBack](https://developer.android.com/guide/topics/ui/accessibility/testing) | Manual Android screen-reader interaction checks | L |
| [Colour Contrast Analyser](https://vispero.com/lp/color-contrast-checker/) | Inspect foreground/background contrast in interface states | L |
| [Stark](https://www.getstark.co/) | Accessibility review within an existing design workflow | B |
| [Pa11y](https://pa11y.org/) | Repeatable command-line accessibility checks | L / F |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

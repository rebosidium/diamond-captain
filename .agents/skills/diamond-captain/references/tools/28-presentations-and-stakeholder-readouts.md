# 28. Presentations and stakeholder readouts

Explain evidence, compare mechanisms and hand off decisions. A polished deck is not a validated problem, an implemented change or evidence of impact.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [PowerPoint](https://www.microsoft.com/en-us/microsoft-365/powerpoint) | Required PPTX delivery or an established team template | B / F |
| [Google Slides](https://workspace.google.com/products/slides/) | Collaborative reviews in Google Workspace | B / A? / F |
| [Keynote](https://www.apple.com/keynote/) | Existing Apple presentation workflow | B / F |
| [Figma Slides](https://www.figma.com/slides/) | Reviews already conducted beside design work | B |
| [Canva](https://www.canva.com/presentations/) | An existing communication template or branded readout | B / F |
| [Pitch](https://pitch.com/) | Team presentation review and shared decks | B / F |
| [Prezi](https://prezi.com/) | An existing spatial presentation format | B |
| [Gamma](https://gamma.app/) | A quick editable narrative draft to verify against sources | B |
| [Beautiful.ai](https://www.beautiful.ai/) | An established template-led presentation workflow | B |
| [Marp](https://marp.app/) | Versioned Markdown slides and local export | L / F |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

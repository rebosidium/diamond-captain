# 3. Documentation and shared decisions

Choose when evidence, briefs, policies or a handoff need a retrievable home. The task-state file remains the recovery point.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Google Docs](https://workspace.google.com/products/docs/) | Shared briefs and reviewable prose | B / F |
| [Notion](https://www.notion.com/) | Linked decisions, task knowledge and lightweight databases | B / A? |
| [Confluence](https://www.atlassian.com/software/confluence) | Team knowledge already lives in Atlassian | B / A? |
| [Superhuman Docs / Coda](https://coda.io/) | Interactive documents combining prose, tables and workflows | B |
| [Microsoft Word](https://www.microsoft.com/en-us/microsoft-365/word) | Document review and a required DOCX handoff | B / F |
| [Obsidian](https://obsidian.md/) | Local Markdown notes with linked evidence | B / F |
| [GitBook](https://www.gitbook.com/) | Searchable product or developer documentation | B / F |
| [Outline](https://www.getoutline.com/) | Team wiki with a self-hosted option | B |
| [Slab](https://slab.com/) | Shared knowledge organized for team discovery | B |
| [ReadMe](https://readme.com/) | API-facing documentation and developer experience work | B |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

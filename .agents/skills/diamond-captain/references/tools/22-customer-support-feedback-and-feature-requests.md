# 22. Customer support, feedback and feature requests

Choose when complaints, workarounds or requests can reveal unmet needs or post-release issues. Support and voting data describe the people who supplied it, not the whole population.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Zendesk](https://www.zendesk.com/) | Search existing support tickets and recurring friction | B / A? |
| [Intercom](https://www.intercom.com/) | Product-support conversations and contextual customer feedback | B / A? |
| [Freshdesk](https://www.freshworks.com/freshdesk/) | Existing customer-service tickets and support operations | B |
| [Help Scout](https://www.helpscout.com/) | Shared support conversations and recurring customer patterns | B |
| [HubSpot Service Hub](https://www.hubspot.com/products/service) | Customer-service evidence tied to existing CRM context | B |
| [Canny](https://canny.io/) | Consolidate feedback and communicate request status | B |
| [UserVoice](https://uservoice.com/) | Existing customer-feedback and prioritization program | B |
| [Featurebase](https://www.featurebase.app/) | Feedback boards, customer support and product updates | B |
| [Productboard](https://www.productboard.com/) | Link customer signals to product planning | B |
| [Survicate](https://survicate.com/) | Gather contextual feedback from actual product users | B |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

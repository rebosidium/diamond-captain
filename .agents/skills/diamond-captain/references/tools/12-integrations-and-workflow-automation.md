# 12. Integrations and workflow automation

Choose when repeated handoffs or operational steps justify automation. Inspect destination, payload, credentials and side effects; use dry runs or local fixtures where possible.

| Candidate | When to consider it | Route to check |
| --- | --- | --- |
| [Zapier](https://zapier.com/) | Connect existing SaaS steps with minimal code | B / A? |
| [Make](https://www.make.com/) | Visual multi-step workflows and data mapping | B / A? |
| [n8n](https://n8n.io/) | Configurable automation with a self-hosting option | B / A? |
| [Pipedream](https://pipedream.com/) | Developer-oriented integrations and event handlers | B / A? |
| [Power Automate](https://www.microsoft.com/en-us/power-platform/products/power-automate) | Automate an existing Microsoft business workflow | B |
| [Workato](https://www.workato.com/) | Existing governed enterprise integration program | B |
| [Activepieces](https://www.activepieces.com/) | Visual workflows in an existing automation workspace | B |
| [Node-RED](https://nodered.org/) | Local or operational event-driven flows | B / L / F |
| [IFTTT](https://ifttt.com/) | Simple supported personal or operational triggers | B |
| [GitHub Actions](https://github.com/features/actions) | Repository-triggered maintenance and validation workflows | B / F |

Use the [shared routing, capability limits and permissions](../tool-options.md#read-only-what-the-next-decision-needs) before acting.

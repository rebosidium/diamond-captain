# Optional tool directions — ten candidates per task category

**24 categories × 10 optional candidates = 240 entries, with deliberate overlap between functions.** This is a practical “top 10 to consider” menu, **not an objective ranking, prescribed stack, installation list or promise of access**. Order does not imply quality. A local note, supplied file or direct conversation can be the best choice.

## Read only what the next decision needs

1. Start with the task, question and existing evidence. Use the routing table below to open only one or two relevant categories; do not read or propose all 240 entries during intake.
2. Prefer the team's existing tool and an **actually available, authorized connector/MCP tool**. Discover its live operations and scopes in the current host; a brand in this file does not prove that a connector exists or is connected.
3. If that route is unavailable, inspect current official API documentation for the needed operation and credentials, or use an authorized browser/app or compatible file. Do not build a new integration just because it appears here. **MCP is a protocol**, not an analytics, research or design product; see its [official introduction](https://modelcontextprotocol.io/).
4. Offer a short recommendation with a reason and a lightweight fallback. Ask the user about their existing workflow or preference when it materially changes the choice; respect their answer. Do independent work that does not depend on it.
5. Before execution, check the actual capability, account permissions, data handling, cost and required output. A public product page proves neither tenant access nor a successful action.

**Route legend, not availability badges:** `B` = browser or native application; `F` = local/file-based workflow where compatible inputs or exports are available; `L` = local executable/runtime, if installed. `A?` = an API route worth investigating in current official documentation; the exact endpoint, plan and scope remain unchecked. Connector/MCP discovery comes first for **every** entry; no row asserts that it is installed. File compatibility and export rights must also be checked.

## Boundaries and a useful fallback

- Do not install, subscribe, upload private research, recruit/pay participants, send messages, share, publish, alter production settings or deploy solely because a tool appears here. Follow the user's scope, prior authorization and governing permission rules; distinguish a question about preference from approval for an external action.
- A read-capable connector may not support creation, editing, export or a specific workspace. An API key does not authorize all resources. Inspect the exact live tool operation before relying on it.
- With no connected tools, keep moving using user-provided evidence, local files, draft artifacts or an explicit proposed study. Record what is unavailable and the resulting decision limit. Never imply that a live session, experiment, release or measurement occurred.
- At a meaningful choice, narrow to a few suitable alternatives or a free-text preference question; do not turn this catalog into a 240-tool questionnaire. The user's engagement preferences and the phase-transition guidance in the main skill control cadence.
- Record the chosen route and why it fits the next decision in task state when material. A tool choice alone is not a phase output or readiness gate.

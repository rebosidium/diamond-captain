# Compatibility and verification

The maintained automated checks cover skill Markdown links, product documentation links, Python syntax, public-content inspection, deterministic host packages, complete pinned core identity and safe native installation. The installation tests cover dry runs, overwrite refusal, backups, path/symlink rejection, receipt failures and state preservation.

Package validation, skill discovery, UI import, actual agent execution and verified live outcomes are different checks. A passing package test does not certify every host/model or a real product outcome. Behavioral scenarios in the core are test definitions; reading them does not make them passed executions.

For a source refactor, check both complete package contents and the agent's actual reference reads. A file in an archive is not proof that its rules were applied. Compare process behavior on the same task inputs and settings; document size alone does not establish token or time savings. Development-source previews and released-package checks have separate source identities.

This renamed release updates product identity, source links and wrapper metadata. Prior host checks from another product identity are not presented as certification of these exact new bytes. Use the current host guides and actual release notes for the scope checked. Internal execution records are not distributed.

See [host routes](host-installation-routes.md), [security](security.md) and the public repository's CI status. No new third-party security certificate is claimed for Diamond Captain at launch.
